# 快捷问答独立后台窗口设计

## 目标

快捷问答必须与主面板无感隔离：提问、生成和多轮上下文都不能创建或激活主面板标签，不能改变主面板当前页面、焦点和快捷键切换顺序。同时，思考过程应在正文出现前持续更新，生成状态不能长时间停留在无反馈的转圈状态。

## 非目标

- 不改为 DeepSeek API，不引入 API Key 或新的计费路径。
- 不阻止 DeepSeek 网页端保存账号历史；这是复用网页版登录态与额度的固有限制。
- 不支持同一快捷会话内并发生成；上一轮完成后才能发送下一轮。
- 不增加新的运行时依赖。

## 方案

`QuickAskWindow` 除现有面板窗口外，再持有一个专用的后台 `BrowserWindow`。后台窗口使用与主面板相同的持久化 partition 和站点 preload，但不加入 `WindowManager` 的标签集合。

后台窗口创建时先位于所有显示器工作区之外，页面加载完成后通过 `showInactive()` 进入可见运行态。窗口设置为无边框、不可聚焦、不进入任务栏，并关闭后台节流。不能使用 `hide()`、零尺寸、零透明度或被主视图遮挡的 `WebContentsView`，因为实测这些方式会让 DeepSeek 暂停生成。

主面板与后台窗口之间没有导航关系。主面板关闭、切换标签或改变窗口尺寸时，快捷问答会话不受影响；应用退出时统一销毁后台窗口。

## 组件职责

### `QuickAskWindow`

- 创建、复用和销毁后台网页窗口。
- 在首次提问前等待后台页面与输入框就绪。
- 把问题发送到后台窗口，并维护快捷面板的多轮状态。
- “新会话”只让后台窗口回到站点首页并清空快捷面板状态。
- 后台渲染进程异常退出时允许重建一次；重建后提示上下文已重置，不伪装为原会话仍然存在。

### 站点 preload

- 继续负责填写输入框、触发发送和读取网页 DOM。
- 从最新助手轮次独立读取思考内容与正文；正文容器尚未出现时也能返回思考增量。
- 约每 200ms 检查一次变化，只在内容指纹改变时推送，避免无意义重绘。
- 回复稳定后停止监听；超时仍保留目前已取得的内容。

### 快捷面板渲染层

- 展示“正在发送 → 正在思考 → 正在回答 → 完成”的明确阶段。
- 思考内容生成时自动展开，正文首次出现后自动收起；用户手动开合后不再覆盖其选择。
- 使用一个克制的呼吸点表示活动状态，并尊重 `prefers-reduced-motion`。
- 移除“展开到主窗口”，保留“新会话”、复制和关闭操作。

### IPC

只有后台窗口的 `webContents` 可以向快捷面板提交 `prompt-result` 和 `answer`。来自主面板标签或旧后台窗口的同名事件必须忽略，防止串轮和串会话。

## 数据流

1. 用户在快捷面板提交问题。
2. 主进程确保后台窗口存在且站点输入框已经就绪。
3. 主进程先启动答案监听，再把问题送入后台窗口。
4. 站点 preload 分别读取思考和正文增量，经 IPC 回传。
5. 主进程只更新当前轮次，快捷面板增量渲染变化部分。
6. 文本稳定或达到超时后结束本轮；后台窗口继续保留，以维持下一轮上下文。

## 错误处理

- 页面未登录、被拦截或找不到输入框：在当前轮显示可操作错误，不改变主面板。
- 后台窗口意外进入屏幕工作区：立即重新停放并记录日志。
- 后台渲染进程崩溃：销毁旧窗口，下一次提问时重建；快捷面板明确提示上下文已重置。
- 两分钟无新回复：结束生成态，显示超时及已取得的部分内容。

## 验收与测试

真实端到端测试连续发送两轮相同问题，并断言：

1. 主面板活动标签 ID、标签快照和页面地址在测试前后完全一致。
2. 后台窗口不在任务栏、不获取焦点，边界位于所有显示器工作区之外。
3. 后台页 `document.visibilityState` 为 `visible`，两轮均正常完成并复用同一网页会话。
4. 完成前至少观察到两个不同长度的思考快照，证明思考内容持续增量更新。
5. 快捷面板最终渲染两轮内容，思考区自动折叠，状态动画在完成后停止。
6. 静态检查、preload 构建和 `git diff --check` 通过。

## 迁移

移除当前把快捷问答建模为主窗口内部标签的代码，以及为隐藏标签增加的过滤逻辑。保留已经验证有效的多轮状态、相同答案轮次识别和 Markdown 安全渲染。
